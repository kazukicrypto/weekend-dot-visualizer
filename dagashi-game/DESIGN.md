## 1. 概要

昭和の町角にある駄菓子屋を一人称3Dで切り盛りし、子どもたちに愛される「町一番の駄菓子屋」に育てる経営シム。AIで量産した小物の3Dモデルを主なコンテンツにして、個人開発で短期間・低コストで作り、Steamの買い切り有料ソフトとして売る。

**一言ピッチ（ストア用）**: お年玉を握りしめた子どもたちがやってくる。仕入れて、並べて、くじを作って、昭和の駄菓子屋を切り盛りしよう。

## 3. コアゲームループ

1日＝約20分のサイクルを繰り返し、稼いだお金で店を広げていく。

```
朝: 仕入れ → 陳列・値付け → 昼〜夕: 営業 → 夜: 精算 → 投資 → （翌日へ）
(問屋に注文)  (棚に並べる)   (接客・お釣り)  (売上と評判)  (新商品・什器)
              (値段を決める) (くじ・ミニゲーム)(常連の好感度) (店の改装)

長期の進行: 店レベル → 商品と什器が解禁 → 図鑑が埋まる → 町一番の駄菓子屋
```

遊びの中心は「営業」で、子どもとのやり取りとくじが配信映えする場面になる。投資で商品が増えるたびに、翌日の仕入れと陳列の選択肢が広がる。

## 4. ゲームシステム詳細

中心になるのは「子どもの少ないお小遣いに合わせて、何をいくらで並べるか」という判断。各システムはこの判断を面白くするためにある。すべて発売版に含める。

| システム | 内容 |
| --- | --- |
| 仕入れ | 問屋のカタログから箱単位で注文し、翌朝届く。問屋ランクで商品が解禁される |
| 陳列 | 棚・瓶・吊り下げ・ガラスケース・冷蔵ケース（ラムネ、アイス）に物理で置く。見栄えが集客に効く |
| 値付け | 10円単位で設定。高すぎると子どもが買えず評判が下がる |
| レジ | 小銭でお釣りを渡す。慣れると「そろばん」で自動化 |
| 客 | 子ども（所持金・好みあり）、大人（懐かし買いで大量購入）、季節客。万引きも発生 |
| 常連との絆 | 常連10人に名前と好感度。一定値で「これ入れて」などの依頼イベント |
| 当てくじ | 景品を選んで台紙を作る。当たり率が低すぎると評判が下がる。当たりつき駄菓子の交換も |
| ミニゲーム | 型抜き、ベーゴマ、めんこ、店頭の10円ゲーム機（4種すべて） |
| 店舗拡張 | 内装、軒先ベンチ、ゲーム筐体、奥の上がり框、隣の空き地 |
| 季節・イベント | 冬休み・お正月から開店（お年玉で子どもの所持金が増える）、雪の日、節分、春休み、夏祭りの出店、新商品入荷 |
| 進行 | 店レベルで商品・什器が解禁。商品図鑑と町の評判で達成感を作る |

**ゲームのゴール**: 評判を最大にして「町一番の駄菓子屋」になるとエンディング。その後もエンドレスで図鑑集めを続けられる。

**商品名はすべてオリジナル**: 実在の駄菓子名やパッケージは使わず、「それっぽい」架空の商品にする。

## 5. コンテンツ規模とAIアセット量産

発売時から小物約540点を入れる。商品の種類の多さがそのまま遊びの量になるので、ここにAI量産を集中させる。

| カテゴリ | 点数 | 形式 |
| --- | --- | --- |
| 駄菓子 | 200 | 3D |
| おもちゃ・景品 | 120 | 3D |
| くじ台紙・ブロマイド | 80 | 2Dテクスチャ |
| 什器（棚・瓶・ケース） | 40 | 3D |
| 店舗・町の小物 | 100 | 3D |
| **合計** | **540** | |

**量産の手順**
1. **コンセプト画像を生成**: 画風を固定したプロンプトと参照画像で、正面からの商品画像を作る
2. **3D化**: 画像から3Dを作る生成AIでモデル化する
3. **自動で軽量化**: Blenderのスクリプトでポリゴン数を削る（小物3,000三角形以下、テクスチャ512px）
4. **自動で整える**: 同じスクリプトでサイズ・原点・当たり判定を設定する
5. **文字を差し替える**: パッケージの文字は崩れやすいので、日本語のラベル画像を貼り替える
6. **データ登録**: 商品表（CSV）にID・名前・仕入れ値・売価・人気・解禁条件を書き、ゲームへ自動で取り込む
7. **目視チェック**: 店に並べた状態で画風が浮いていないか確認する

**画風をそろえるルール**: トゥーンシェーダーを全商品に掛け、色数を決めたパレットに寄せる。モデルごとの小さなばらつきは、この2つでほぼ目立たなくなる。

## 6. アート・サウンド・世界観

「冬休みの夕暮れ、ストーブのある駄菓子屋にお年玉を持って寄った記憶」を一枚絵で伝えることが目標。スクリーンショット1枚で世界観が伝わるかが、Steamでのクリック率を左右する。

- **舞台**: 昭和の地方の町。雪の積もった木造の小さな店と、前の道、小学校への通学路。店内には石油ストーブ、奥の上がり框にこたつ、軒先に正月飾り。福袋や凧・こまなど正月の商品も並ぶ
- **画風**: 柔らかいトゥーン調。写実に寄せない（AIモデルの粗が目立たず、軽くもなる）
- **光**: 朝・昼・夕方で色味が変わる。1日の時間の流れを光で見せる
- **音**: ストーブの音、雪を踏む音、子どもの声、小銭の音、店のラジオ（季節が進むと蝉や風鈴に変わる）。BGMは控えめにして環境音を主役にする
- **UI**: 手書きの帳簿や問屋の注文書風。画面の文字も世界観の一部にする

### トンマナ案（推奨: A＋B「手のひらサイズの昭和」）
- **コンセプト**: 「冬の夕暮れ、外は雪、中はストーブで温かい」。この外と中の対比を全画面の基本にする
- **色**: ベースはくすませた暖色（木の茶、ストーブの橙、畳の黄緑）。外は雪の青白さと夕暮れの群青。駄菓子のパッケージだけビビッドな原色にして商品を主役にする
- **光**: 店内は電球とストーブの橙、窓の外は青。夕方が一番きれいに見えるように設計
- **形**: 角は少し丸く、輪郭線なし（または細め）。比率を少しデフォルメしておもちゃっぽい可愛さを出す
- **質感**: 紙・木・ガラス瓶だけ丁寧に作り、それ以外はシンプルな塗り
- **人物**: 顔は簡略化、表情は記号的に（リアルな人間は破綻しやすい）
- **UI**: 手書きの値札、問屋の伝票、昭和のチラシ風。丸ゴシック＋手書き風フォント
- **やらないこと**: 写実、ホラーっぽい暗さ、実在の商品やロゴ、特定作品の画風の模倣

## 7. 技術構成

Unityを推奨。店舗シムの作り方の情報やアセットが最も多く、AIにコードを書かせたときの精度も高い。

| 項目 | 方針 |
| --- | --- |
| エンジン | Unity 6（URP）。費用を抜きたい場合はGodotも可 |
| 操作 | 一人称。拾う・置く・回すの3操作で完結。ゲームパッド対応 |
| 商品データ | CSVを原本にし、起動時に読み込む。商品の追加は行とモデルを足すだけ |
| セーブ | JSONでローカル保存＋Steamクラウドセーブ |
| Steam連携 | 実績、クラウドセーブ。ワークショップは後回し |
| 軽さの目標 | Steam Deckで安定30fps。小物はまとめて描画し、遠くは簡略表示に切り替える |
| 客の動き | 通常の経路探索＋「欲しいもの・所持金・気分」の単純な状態遷移 |

**開発環境はMac**: 開発はMacで行い、Windows版はUnityのMac上から書き出す（スクリプトの実行方式はMono。IL2CPPのWindows版はWindows PCが必要）。売上の大半はWindowsなので、動作確認は次の3段階で行う。
1. **日常の確認**: Mac上の仮想Windows（Parallels）で起動と基本操作を確かめる
2. **実機に近い確認**: Steam DeckでWindows版を動かす（Deck対応の確認も兼ねる）
3. **幅広い確認**: 体験版の前にSteam Playtestで他人のWindows PCで遊んでもらう。不安が残れば安いWindowsの小型PCを購入する

Mac版はApple Developer Program（年$99）に登録して公証する。Steamへのアップロードもmacから可能。

## 8. 収益化と販売戦略

買い切り$9.99〜$12.99で発売し、売上は「発売前に集めたウィッシュリストの数」でほぼ決まる。開発と同じ重さで宣伝を進める。

**価格**
- 基本は$12.99（ガチャ店シムと同等）。Next Festでの反応が弱ければ$9.99
- 発売から1週間10〜15%オフ
- 日本円価格はSteamの推奨換算を使う

**売上の目安（粗い試算）**: 1万本 × $12.99 × 手取り約50%（Steam手数料30%、地域価格、セール、返金、税を差し引いた分）≈ 約$6.5万。

**宣伝の流れ**
1. **Steamページを早く公開**: 11月中に「近日登場」として公開（Next Fest参加の前提）。カプセル画像とスクショ5枚、短い動画を用意する
2. **短い動画を毎週SNSへ**: TikTok、X、YouTube Shorts。「商品を並べる気持ちよさ」「くじの大当たり」など3秒で伝わる場面を切り出す。年末年始は「お年玉」「福袋」ネタで投稿を集中させる
3. **開発過程も発信**: 「AIで540個の駄菓子を作った」自体が話題になる。ただしAIへの反感に配慮して見せ方を選ぶ
4. **体験版でSteam Next Fest（2027年2月）に参加**: ウィッシュリストが最も伸びる機会。終了後1ヶ月以内に発売して勢いを逃さない
5. **配信者にキー配布**: 日本と海外の店舗シム配信者へ、発売の2週間前に送る
6. **発売後の無料アップデート**: 季節イベントや商品追加。ストアでの露出が伸び、セールのタイミングも作れる

**目標のウィッシュリスト**: Next Fest前に3,000件、発売時に1万件以上。

### Steam Next Festとは
Steamが年3回（2月・6月・10月）開く、発売前のゲームの体験版を集めた1週間のオンラインイベント。参加無料・個人開発でも可。参加できるのは**未発売の作品だけ**なので、発売はNext Festの後にする。

## 10. リスクと対策

一番大きいリスクは「作り込みすぎて発売が遅れること」。全部入りを1ヶ月で作るので、11月末で機能追加を締め切り、残りの期間は調整と宣伝に使う。

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 作り込みすぎ | 発売延期、資金と意欲の消耗 | 11月末で機能追加を締め切る。新しい案は「発売後リスト」へ |
| 経営シムの中盤が単調 | 低評価レビュー | 2〜3時間ごとに新しい什器・ミニゲーム・客を解禁する |
| AI使用への反感 | レビューやSNSでの批判 | SteamのAI開示を正直に書く。「設計・ゲーム性は手作り」を伝える |
| 生成AIの利用規約 | 販売できない素材が混ざる | 商用利用OKのプランのみ使う。使ったツールと日付を記録する |
| 実在商品に似る | 商標・意匠のトラブル | 商品名・パッケージはオリジナル。実在商品名をプロンプトに入れない |
| 画風のばらつき | 安っぽく見える | トゥーンシェーダーとパレットで統一。目視チェックを工程に入れる |
| 動作が重い | Steam Deckで遊べない | 商品を並べた状態で毎週テストする |
| 競合の参入 | 「初の駄菓子屋シム」の立場を失う | Steamページを早く公開して先に名乗りを上げる |
