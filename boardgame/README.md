# ボードゲーム メカニクス・データベース

自作ボードゲームを設計するためのリファレンス。
公開URL: https://kazukicrypto.github.io/weekend-dot-visualizer/boardgame/

## 中身

| ファイル | 内容 |
|---|---|
| `mechanics.js` | メカニクス **95件**（17カテゴリ）。効果・注意点・相性・代表作つき |
| `games.js` | 代表作カタログ **82件**。採用メカニクスと「盗める設計」つき |
| `db.json` | 上記2つを結合した機械可読エクスポート |
| `index.html` | 検索・絞り込み・発想支援ができるビューア（単一HTML・依存なし） |

## メカニクスの項目

```js
{
  id:"worker-placement",       // 一意ID（games.js から参照）
  ja:"ワーカープレイスメント",
  en:"Worker Placement",
  cat:"worker",                // 17カテゴリのいずれか
  weight:3,                    // 総合の重さへの寄与 1(軽)-5(重)
  downtime:2,                  // 待ち時間の増えやすさ 1(短)-3(長)
  players:"2-5",               // 特に機能しやすい人数帯
  desc:"…",                    // 何をするメカニクスか
  effect:"…",                  // プレイヤーの判断・体験にどう効くか
  goodWith:["turn-order-variable", …],  // 相性のよいID
  caution:"…",                 // 典型的な失敗と回避策
  games:["アグリコラ", …]
}
```

## カテゴリ

手番構造 / アクション選択 / ワーカー系 / 資源・経済 / カード / デッキ・バッグ構築 /
ダイス・運 / エリア・盤面 / 移動 / タイル・パズル / 競り・入札 / 交渉・心理 /
情報・推理 / 協力・非対称 / 得点・終了条件 / リアルタイム・体感 / キャンペーン・成長

## 使い方（設計の手順）

1. **骨格を1つ選ぶ** — 手番構造・アクション選択・ワーカー・デッキ・移動 から1つ。
   ここでゲームの「1手番に何をするか」が決まる。
2. **味付けを1〜2つ** — カード / ダイス / 資源 / エリア / タイル / 競り / 得点 から。
   3つ以上乗せると、ほぼ確実に重くなりすぎる。
3. **制約を1つ** — 交渉 / 情報 / 協力 / リアルタイム / キャンペーン から。
   「〜してはいけない」が面白さの核になることが多い（例：ボーナンザの手札並べ替え禁止）。
4. ビューアの **「組み合わせ発想」タブ** がこの3ステップをランダムに引く。
5. 各メカニクスの `caution` を必ず読む。既知の地雷はほぼそこに書いてある。

## 出典について

BoardGameGeek のメカニクス分類を下敷きにしつつ、実プレイでの体感（重さ・待ち時間・
人数適性）と設計上の勘所を日本語で書き下ろしたもの。分類名は BGG と一対一ではない。
